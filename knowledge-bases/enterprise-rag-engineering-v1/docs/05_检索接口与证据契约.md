# 检索接口与证据契约

## 核心调用

输入遵循现有项目的 `retrieval_request.schema.json`：

```json
{
  "retrieval_request_id": "uuid",
  "knowledge_base_version_id": "uuid",
  "query_text": "如何评估混合检索？",
  "top_k": 5,
  "filters": {"max_difficulty_level": 4, "is_core": true}
}
```

兼容响应只返回：`retrieval_request_id` 与 `evidence_items`。每个证据包含 `evidence_id`、`chunk_id`、`document_id`、`content_excerpt` 和 `relevance_score`，可直接通过现有 JSON Schema。

## 责任边界

- 前端不得直接访问知识服务；
- 业务后端注入知识版本、组织和权限过滤；
- Retrieval Agent 只提出查询和策略，不拥有扩大权限的能力；
- Generation Agent 使用 evidence_ids 生成资源；
- Review Agent 重新读取证据并检查支持关系；
- Arbitration Agent 只能选择已通过审核的提案。
