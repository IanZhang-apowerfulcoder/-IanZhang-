# 知识库交付验收检查表

## A. 内容完整性

- [ ] `data/domain.json` 明确领域、目标用户、范围和质量目标。
- [ ] 8 个模块、32 个知识节点、128 个专业切片数量与报告一致。
- [ ] 每个核心知识节点至少具备概念卡、FAQ、误区、题目、任务、Rubric 和检索评测案例。
- [ ] 所有专业结论能够追溯到 `source_ids` 和 `evidence_id`。
- [ ] 生成内容不得反向写入权威知识库。

## B. 契约与接口

- [ ] `contracts/knowledge-api.yaml` 可解析，所有本地 `$ref` 有效。
- [ ] `/api/v1/retrieval/search` 与现有项目检索 Schema 兼容。
- [ ] Diagnosis、Path、Resource、Assessment、Review、Arbitration 示例均通过现有 Schema。
- [ ] 后端固定使用 `knowledge_base_version_id`，不得查询未发布候选版本。

## C. 质量门禁

```bash
python scripts/validate_pack.py
python scripts/run_retrieval_eval.py
pytest -q
```

- [ ] Schema 与引用校验 100% 通过。
- [ ] 核心内容覆盖率达到 100%。
- [ ] 固定词法检索基线 Hit@5 不低于 90%。
- [ ] 不存在伪造向量、伪造幻觉率或伪造难度适配率。
- [ ] 真实模型接入后另行测量专业谬误率、难度适配率和引用正确率。

## D. 比赛提交

- [ ] 提供至少 1 个垂直领域专业知识库切片。
- [ ] 提供不少于 2 组差异化学习者完整输入输出，本包提供 3 组。
- [ ] 演示可展示画像输入、检索证据、多智能体中间结果和个性化资源。
- [ ] 数据合规声明、来源治理说明和部署说明齐全。
