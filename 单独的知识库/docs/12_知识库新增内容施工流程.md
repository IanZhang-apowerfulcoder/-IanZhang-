# 知识库新增内容施工流程

## 一、原则

知识库升级采用不可变版本。任何资料新增、删除、重新切片、来源变更、嵌入模型更换或图关系重构，都创建候选版本，不直接修改当前激活版本。

## 二、施工步骤

1. **来源准入**：用 `templates/source_record.template.json` 登记来源、版本、可信等级、许可状态和适用范围；
2. **知识建模**：将内容映射到现有节点，确有独立能力目标时再新增节点；
3. **节点编写**：使用 `knowledge_node.template.json`，补齐事实、误区、边界、前置知识和学习目标；
4. **切片与证据**：每个切片应自包含，绑定来源、知识节点、难度、版本和 evidence_id；
5. **教学资产**：核心节点至少补齐题目、任务、Rubric、FAQ、误区案例和评测案例；
6. **索引构建**：先运行词法/元数据基线，再按冻结的 embedding 模型生成向量；
7. **回归评测**：运行检索、生成、拒答、安全、难度适配和引用正确率测试；
8. **差异审核**：审查新增、删除、冲突、低分节点和失败案例；
9. **候选发布**：形成候选质量报告，保持当前生产版本不变；
10. **人工批准**：负责人批准后才切换激活版本，并保留回滚指针。

## 三、最小验收命令

```bash
make validate
make compatibility
make eval
make test
```

## 四、禁止事项

- 不允许将模型自由生成的专业事实直接写入权威库；
- 不允许删除来源或证据链以简化接口；
- 不允许在评测集上手工写死检索答案后宣称泛化能力；
- 不允许用检索 Hit@K 替代幻觉率、难度适配率或用户效果；
- 不允许把候选版本标记为正式发布而没有审批记录。
