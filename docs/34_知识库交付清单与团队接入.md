# 知识库交付清单与团队接入

## 1. 权威目录

```text
knowledge-bases/enterprise-rag-engineering-v1/
```

该目录是当前项目的预建专业知识库唯一事实标准。学习闭环默认读取此版本，不在学习者每次使用时重新生成知识库。

## 2. 各成员接入边界

| 角色 | 应使用的内容 | 禁止行为 |
|---|---|---|
| 后端 | `api/knowledge_domain_api.yaml`、数据库迁移、Domain Pack ID/Version ID | 不得绕过版本和审核直接读任意候选资料 |
| 检索/RAG | `data/rag_chunks.jsonl`、节点/关系、评测集、检索接口 | 不得伪造向量或替换 evidence_id |
| 诊断/路径 Agent | 节点、前置关系、题目映射和 learner cases | 不得直接修改知识库内容 |
| 资源/测评 Agent | Retrieval Response、题库、任务、Rubric | 专业结论必须引用 evidence_id |
| 审核/仲裁 Agent | 原始证据、边界、误区和审核示例 | 不得只依据生成 Agent 自评通过 |
| 前端 | 后端公开 API 返回的资源、证据和状态 | 不得直接访问数据库或知识包文件路径 |
| 测试 | `reports/`、`data/*eval_cases.json`、`submission/` | 不得把词法检索指标冒充幻觉率 |

## 3. 本地启动与验证

```bash
cd knowledge-bases/enterprise-rag-engineering-v1
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
make validate
make compatibility
make eval
make test
make serve
```

Windows PowerShell 使用 `.venv\Scripts\Activate.ps1`。

## 4. 数据库接入

```bash
python scripts/import_to_postgres.py --dry-run
python scripts/import_to_postgres.py --dsn "$DATABASE_URL"
```

先执行 `database/migrations/002_enterprise_rag_domain_pack.sql`，再导入数据。正式业务必须固定 `knowledge_base_version_id`。

## 5. 验收事实

- 8 个模块；
- 32 个知识节点，其中 26 个核心、6 个高级；
- 91 条知识关系；
- 128 个专业切片；
- 128 道题、32 个工程任务、32 套 Rubric；
- 96 条检索评测、32 条生成评测；
- 3 组差异化学习者完整输入输出；
- 现有六智能体 Schema 兼容检查通过；
- 本地固定词法检索基线 Hit@5 为 100%。

完整限制与未测指标见：

```text
knowledge-bases/enterprise-rag-engineering-v1/reports/final_validation_report.md
```

## 6. 变更规则

1. 已发布知识包不可原地修改；
2. 新内容必须创建候选版本；
3. 所有新增专业结论必须登记来源；
4. 重新切片、换 embedding 模型或改元数据都需要重跑检索回归；
5. 未通过质量门禁不得切换为当前激活版本；
6. Agent 生成的讲义和题目属于派生资源，默认不反向进入权威知识库。
