# 端到端用户流程与接口审计

## 审计结论

V4 的接口数量确实偏少。它能够演示“开始学习—看资源—做测评”，但缺少系统真正上线需要的身份、培训项目、分配关系、知识库版本、异步事件、行为数据、人工审核、画像历史和可观测性接口。V5 已补齐当前产品范围内的主要边界。

## 流程 A：企业管理员建立并发布知识库

1. 登录，获得 `user_id` 和 `organization_id`。
2. 创建 `knowledge_base_id`。
3. 上传文件，服务端生成 `document_id` 和 `content_sha256`。
4. 发起构建，生成 `build_run_id`。
5. 轮询任务或读取事件，状态通过 `build_status` 表示。
6. 构建完成生成 `knowledge_base_version_id`、`version_no`、`quality_report_id`。
7. 运行检索评测，生成 `retrieval_test_run_id`。
8. 质量达标后发布并激活版本。

接口覆盖：知识库、文档、构建任务、构建事件、版本、质量、检索测试、知识图谱、发布和激活接口均已定义。

## 流程 B：企业管理员创建培训项目并分配学习者

1. 选择已激活的 `knowledge_base_version_id`。
2. 创建 `training_program_id`。
3. 配置目标知识节点 `program_target_node_ids`。
4. 发布培训项目。
5. 批量传入 `learner_ids`，为每人创建 `assignment_id`。
6. 学习者端按 `learner_id` 查询自己的任务。

接口覆盖：培训项目增改查、发布、任务分配、学习者任务列表和任务详情均已定义。

## 流程 C：学习者完成一轮闭环学习

1. 学习者使用 `assignment_id` 启动会话。
2. 后端创建 `session_id`，固定知识库版本与基础画像快照。
3. 编排器创建 `decision_cycle_id`。
4. 诊断、路径、资源、测评、审核、仲裁智能体按统一信封运行。
5. 每次调用创建独立 `agent_run_id`，每份候选方案创建 `proposal_id`。
6. 审核产生 `review_id`，仲裁产生 `decision_id`。
7. 动作执行器产生 `action_execution_id`，当前动作通过 `action_type + reference_id` 返回。
8. 学习者查看资源并上报进度与行为事件。
9. 学习者提交类型化答案，创建 `attempt_id`。
10. 评分服务产生掌握度增量，并触发下一 `decision_cycle_id`。
11. 画像服务创建新的 `profile_snapshot_id` 和 `profile_version_no`。
12. 系统继续下一轮或完成 `session_id`。

接口覆盖：会话、决策轮次、当前动作、事件、资源、进度、测评、结果、行为、反馈、最终决策、画像、路径、人工审核、智能体运行详情、证据和指标均已定义。

## 流程 D：低置信度或冲突进入人工审核

1. 审核或仲裁识别高风险结果。
2. 创建 `human_review_task_id`。
3. 管理员查看提案、证据和冲突原因。
4. 提交 `resolution_code` 和必要修订数据。
5. 产生人工审核完成事件，携带原 `decision_cycle_id`。
6. 编排器恢复同一决策轮次或创建新的决策轮次，具体由 `resume_policy` 决定。

## 仍不在本期范围内

- 计费、合同、发票；
- 外部企业目录同步；
- 大规模实时协作编辑；
- 完整运营工单系统；
- 独立微服务管理面板。

这些不应在第一版继续扩展接口，否则会稀释多智能体联合决策的核心。
