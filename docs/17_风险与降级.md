# 风险与降级

## 主要风险

### 1. 项目变成顺序流水线

控制：必须展示分歧、审核、驳回、重试和仲裁记录。

### 2. 智能体输出不稳定

控制：JSON Schema、最多重试、规则兜底、Mock 降级和人工介入。

### 3. 基础成员让 AI 擅自改接口

控制：契约文件只由 Owner 批准，CI 检查，任务卡限定文件范围。

### 4. 前端直接依赖原始输出

控制：后端展示适配层和固定 View 类型。

### 5. 题目泄漏答案

控制：内部测评模型与公开视图分离，接口测试验证不返回答案。

### 6. 数据串租户

控制：服务层强制组织过滤、数据库索引、越权回归和审计。

### 7. 核心成员负载过高

控制：先固定契约和 Mock，再并行；成长型成员只做边界明确的实现。

## 演示降级

- 外部模型不可用：切换固定 Mock Provider。
- 向量服务不可用：使用预构建本地评测索引。
- 异步任务失败：展示已保存的成功会话回放。
- 网络不稳定：准备本地部署和演示数据。

降级结果必须明确标记为演示模式，不能伪装成实时调用。
