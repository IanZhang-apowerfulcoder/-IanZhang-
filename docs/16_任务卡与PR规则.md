# 任务卡与 Pull Request 规则

## 一张合格任务卡

必须写清：

- 任务负责人和审核人。
- 业务目标。
- 允许修改文件。
- 禁止修改文件。
- 输入接口。
- 输出接口。
- Mock 文件。
- 正常和异常验收用例。
- 测试命令。

模板见 `templates/TASK_CARD.md`。

## PR 规则

成长型成员：

- 一个 PR 一个任务。
- 不修改公共契约，除非任务就是契约变更。
- 必须附页面截图或接口测试结果。
- 必须说明自己测试了哪些状态。
- 收到修改意见后在原分支继续提交，不新建第二个 PR。

核心成员：

- 负责检查接口、状态、权限、异常和测试。
- 不应只检查页面是否“看起来能用”。

## 合并方式

普通功能使用 `Squash and merge`。合并后删除功能分支，并从最新 `develop` 创建下一任务分支。
