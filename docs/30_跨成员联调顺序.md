# 跨成员联调顺序

## 第一阶段：契约冻结

- 张英赫确认会话、轮次、仲裁和最终动作字段。
- 李佳乐确认知识、证据、审核和人工审核字段。
- 杨欣怡确认诊断、路径、资源、测评和画像字段。
- 陈尧确认前端展示模型是否足够，但不能要求前端直接读取模型原始输出。

## 第二阶段：全部使用Mock并行开发

- 陈严谨使用管理端API Mock。
- X使用学习端与决策轨迹Mock。
- 郑翘楚使用资源智能体与资源API Mock。
- 李汝萱使用测评智能体与测评API Mock。
- 陈尧使用轨迹、证据、画像和指标Mock。
- 斯汀检查所有Mock的成功、空数据和失败状态。

## 第三阶段：按依赖替换真实实现

1. 李佳乐先替换知识工程、检索和证据Mock。
2. 杨欣怡替换诊断、路径和画像Mock。
3. 郑翘楚替换资源智能体Mock。
4. 李汝萱替换测评智能体和评分Mock。
5. 李佳乐替换审核智能体Mock。
6. 张英赫替换仲裁、动作执行和会话编排Mock。
7. 陈尧和X接入真实决策轨迹。
8. 斯汀执行端到端回归。

## 联调失败时的责任判断

- 字段名或类型不一致：实现方负责修复，契约不随意修改。
- 契约确实缺字段：契约负责人发起变更流程。
- Mock与契约不一致：Mock维护人斯汀修复，契约负责人审核。
- 前端页面缺状态：页面实现人修复。
- 智能体输出不合法：对应智能体实现人修复。
- 编排顺序、重复调用或状态错误：张英赫修复。
