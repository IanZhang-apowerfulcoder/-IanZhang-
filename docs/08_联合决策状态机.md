# 多智能体联合决策状态机

## 主状态

```text
created
-> collecting_context
-> diagnosing
-> planning
-> generating_resource
-> reviewing_resource
-> delivering_resource
-> generating_assessment
-> reviewing_assessment
-> awaiting_submission
-> evaluating_result
-> arbitrating
-> updating_profile
-> completed
```

异常状态：

```text
retrying
waiting_human_review
failed
cancelled
```

## 决策规则

1. 诊断输出未通过 Schema：最多重试 2 次，仍失败则人工处理。
2. 诊断置信度低于阈值：补充前测或历史证据。
3. 路径与诊断结论冲突：审核智能体检查，仲裁智能体决定重规划或接受。
4. 资源证据覆盖不足：驳回并重新生成，不展示给用户。
5. 测评答案不可验证：驳回并重新生成。
6. 同一步骤连续失败 3 次：停止自动循环，进入人工处理。
7. 任何跨租户证据：立即失败并记录安全事件。

## 事件序列

每次状态变化写入 `agent_events`：

- `sequence_no` 必须递增。
- 事件不可原地覆盖。
- 前端通过事件列表构建时间线。
- 最终决策必须能追溯到输入提案和证据。

## 分歧定义

以下任一情况视为分歧：

- 诊断建议复习，路径建议直接测评。
- 两个候选路径优先级不同且差值超过阈值。
- 审核智能体否决生成结果。
- 生成结果置信度高，但证据覆盖不足。
- 新测评结果与当前画像明显冲突。

## 人工介入

人工介入必须记录：

- `human_reviewer_id`
- `override_action`
- `override_reason`
- `original_decision_id`
- `created_at`

不得只在页面上手工改状态而不留审计记录。
