# 前端、后端与智能体数据流

## 资源展示完整链路

```text
1. 前端创建学习会话
2. 后端编排器调用诊断和路径智能体
3. 后端从知识工程引擎获取证据
4. 资源生成智能体返回 ResourceOutput
5. 后端校验 ResourceOutput Schema
6. 审核智能体审核资源
7. 后端保存原始输出、审核结果和展示版本
8. 前端调用 GET /learning-sessions/{session_id}/resources
9. 后端返回 ResourceView
10. 前端展示资料和引用
```

郑翘楚实现的是第 4 步和第 10 步相关代码，不负责第 2、3、5、6、7 步。

## 测评展示完整链路

```text
1. 编排器确定进入测评
2. 测评智能体生成 AssessmentOutput
3. 后端校验并调用审核智能体
4. 后端保存含答案的内部版本
5. 前端获取 AssessmentView，不含答案
6. 用户提交答案
7. 后端评分并保存结果
8. 前端获取 AssessmentResultView
9. 编排器更新画像并触发仲裁
```

## 页面为什么不能直接用智能体输出

智能体输出包含：

- 内部答案。
- 修复指令。
- 调试警告。
- 可能变化的模型字段。
- 不应该向用户暴露的内部状态。

因此公开接口返回的是稳定展示模型。

## 异步任务

知识构建和完整学习会话是异步任务：

- 创建接口返回 HTTP 202。
- 返回 `session_id` 或 `build_run_id`。
- 前端轮询状态和事件。
- 第一版不要求 WebSocket。
- 后续可在不修改展示模型的情况下增加 SSE。

## 请求标识

每个前端请求必须带或由后端生成 `request_id`。同一次学习会话中的智能体运行共享 `session_id`，每次独立智能体调用有独立 `run_id`。
