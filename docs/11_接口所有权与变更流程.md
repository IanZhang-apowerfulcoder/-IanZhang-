# 接口所有权与变更流程

## 所有权

- 公共响应信封、学习会话、仲裁：张英赫。
- 知识库、证据、知识构建、审核：李佳乐。
- 诊断、路径、资源、测评业务字段：杨欣怡。
- 前端展示模型和可视化字段需求：陈尧。
- 成长型成员是接口实现者或消费者，不是公共契约最终 Owner。

详细表见 `project/interface_owners.yaml`。

## 变更分类

### 非破坏变更

- 新增可选字段。
- 新增枚举值且消费者有未知值兜底。
- 新增接口。

### 破坏变更

- 删除或重命名字段。
- 修改字段类型。
- 修改必填性。
- 修改枚举原有含义。
- 修改状态机顺序。
- 修改权限范围。

## 流程

1. 提交 `templates/API_CHANGE_REQUEST.md`。
2. 标注受影响的前端、后端、智能体、数据库和测试。
3. 契约 Owner 审核。
4. 张英赫批准跨模块破坏变更。
5. 先修改 OpenAPI、Schema、类型和 Mock。
6. 契约 PR 合并后再修改实现。
7. 所有消费者完成迁移后才能删除旧字段。

禁止先改代码、后补接口文档。

## 兼容窗口

破坏变更原则上提供一个阶段的兼容期。旧字段标记 `deprecated`，新旧字段同时返回，前端迁移完成后再删除。
