# 异步任务、轮询与状态规则

## 1. 需要异步处理的任务

- 文档解析；
- 知识库构建；
- 检索评测；
- 学习会话中的联合决策；
- 测评自动评分；
- 人工审核等待与恢复。

## 2. 通用状态原则

不同对象必须使用专用状态字段：

- `document_status`
- `build_status`
- `session_status`
- `decision_cycle_status`
- `agent_run_status`
- `proposal_status`
- `task_status`
- `attempt_status`
- `execution_status`

禁止跨模块只传 `status`。

## 3. 事件增量读取

客户端保存最后一个 `sequence_no`，下一次请求传 `after_sequence_no`。服务端返回序号更大的事件。客户端发现序号跳跃时必须补拉，不得假设时间戳完全有序。

## 4. 轮询退避

建议：

```text
首次 1 秒
随后 2 秒
随后 3 秒
稳定阶段 5 秒
最长不超过 10 秒
```

页面离开、任务终态或用户取消时停止轮询。未来可替换为服务器推送，但字段和事件模型保持不变。

## 5. 终态

- 成功类：`succeeded`、`completed`、`published`；
- 失败类：`failed`、`rejected`；
- 主动终止：`cancelled`、`archived`；
- 等待类不是终态：`waiting_user`、`waiting_human_review`。

## 6. 重试

- 同一次重试请求复用 `idempotency_key`，不得创建重复业务对象；
- 智能体重试必须创建新的 `agent_run_id`；
- 重试后的新提案必须创建新的 `proposal_id`；
- 原失败运行和提案不得覆盖删除；
- 重试通过 `causation_id` 关联原失败对象。

## 7. 取消

取消请求只是提出取消，响应应返回任务当前状态。已经进入不可撤销提交阶段的任务可以拒绝取消并返回明确错误码。
