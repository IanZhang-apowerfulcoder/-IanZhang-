# 六智能体职责与接口

所有智能体均接收统一请求信封，返回统一结果信封。业务字段分别由 JSON Schema 定义。

## 统一输入

关键字段：

- `schema_version`
- `run_id`
- `session_id`
- `organization_id`
- `learner_id`
- `agent_name`
- `task_type`
- `context_refs`
- `constraints`
- `requested_at`

## 统一输出

关键字段：

- `schema_version`
- `run_id`
- `agent_name`
- `status`
- `output`
- `evidence`
- `confidence`
- `reasoning_summary`
- `warnings`
- `requires_human_review`
- `completed_at`

`reasoning_summary` 只保存可审计的简要理由，不保存或展示模型隐藏推理过程。

## 1. 诊断智能体

负责人：杨欣怡。

输入：画像、前测、历史尝试、行为摘要、知识节点。

输出：

- 已掌握节点。
- 薄弱节点。
- 错因模式。
- 学习需求。
- 证据和置信度。

Schema：`diagnosis_output.schema.json`

## 2. 学习路径规划智能体

负责人：杨欣怡。

输入：诊断输出、目标、先修关系、时间限制。

输出：候选学习路径、步骤、难度、成功条件和备选路径。

Schema：`path_plan_output.schema.json`

## 3. 学习资源生成智能体

实现：郑翘楚。设计和审核：杨欣怡。

输入：路径步骤、用户水平、检索证据、内容约束。

输出：标题、摘要、章节、关键点、代码示例和引用。

限制：不能自行修改路径，不能在无证据时生成确定性知识结论。

Schema：`resource_output.schema.json`

## 4. 测评智能体

实现：李汝萱。设计和审核：杨欣怡。

输入：目标节点、难度、题型约束、知识证据。

输出：题目、标准答案、评分规则、解析和引用。

限制：公开前端接口在用户提交前必须过滤 `correct_answer`、`scoring_rubric` 和内部解析。

Schema：`assessment_output.schema.json`

## 5. 证据审核与纠偏智能体

负责人：李佳乐。

输入：目标智能体输出、原始证据、规则和质量阈值。

输出：批准、驳回、要求修订或人工处理；问题清单和修复指令。

审核必须组合：Schema 校验、引用存在性、证据覆盖、规则检查和语义评审。

Schema：`review_output.schema.json`

## 6. 决策与仲裁智能体

负责人：张英赫。

输入：诊断、路径、资源、测评、审核结果和历史决策。

输出：最终动作、选中方案、拒绝方案、补证据或重试动作、人工介入和理由摘要。

仲裁必须由确定性状态机约束，不能用一个大提示词替代流程控制。

Schema：`arbitration_output.schema.json`

## 自动知识工程引擎

负责人：李佳乐。

它提供：

- 文档构建任务。
- 检索证据包。
- 知识库质量报告。
- 组织权限过滤。

它不属于六个学习决策智能体，但所有智能体通过它获取领域证据。
