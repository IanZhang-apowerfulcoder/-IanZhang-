# 系统模块边界

## 推荐第一版结构

```text
apps/web                 前端
apps/api                 HTTP API、鉴权、展示模型
services/orchestrator    学习会话和智能体编排
services/knowledge       文档、知识构建、RAG、证据
services/agents          六个逻辑智能体
services/evaluation      固定评测与指标
packages/contracts       JSON Schema、TS 类型、Python 模型
packages/shared          错误码、日志、工具
```

## 为什么不拆六个微服务

第一版团队只有四名强成员。拆成六个服务会增加：

- 部署和网络故障。
- 接口鉴权。
- 分布式日志。
- 版本兼容。
- 本地启动难度。
- 成长型成员误操作风险。

因此六个智能体是六个独立模块和六套契约，不是六套服务器。

## 公开接口与内部接口

### 公开接口

给前端使用，定义在 `api/openapi.yaml`。

公开接口只返回稳定展示模型，例如：

- `LearningSessionView`
- `ResourceView`
- `AssessmentView`
- `DecisionTimelineView`
- `FinalDecisionView`
- `LearnerProfileView`

### 内部接口

给编排器调用六个智能体，定义在：

- `api/internal_agent_interfaces.yaml`
- `contracts/jsonschema/`

智能体原始结果不直接返回前端。

## 展示适配层

后端必须执行：

```text
智能体原始输出
-> JSON Schema 校验
-> 权限和租户校验
-> 持久化
-> 隐私和答案过滤
-> 转换为前端展示模型
-> 公开 API 返回
```

这样资源智能体或测评智能体内部字段调整时，前端不会立即崩溃。

## 禁止依赖

- 前端禁止直接调用大模型。
- 前端禁止调用 `/internal/` 接口。
- 资源智能体禁止修改学习路径。
- 测评智能体禁止修改画像。
- 审核智能体禁止直接执行最终动作。
- 仲裁智能体禁止绕过审核读取未经校验结果。
- 成长型成员禁止新增第二套公共类型。
