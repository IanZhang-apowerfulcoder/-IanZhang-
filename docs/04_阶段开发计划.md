# 分阶段开发计划

## 阶段 0：契约冻结与练习

目标：没有真实功能前，先把团队协作和接口定死。

必须完成：

- 仓库、分支保护、PR 模板、责任人。
- OpenAPI、错误码、字段字典和六智能体 JSON Schema V1。
- 数据库基线。
- 每个公开接口至少一个 Mock。
- 所有人完成一次练习 PR。

门禁：任何人都能说明自己的输入、输出、依赖和验收标准。

## 阶段 1：Mock 纵向闭环

目标：前端和后端不等待真实智能体，先用固定 Mock 跑通全流程。

流程：

```text
创建学习会话
-> Mock 诊断
-> Mock 路径
-> Mock 资源
-> Mock 审核
-> Mock 测评
-> Mock 仲裁
-> 页面展示时间线和最终决策
```

门禁：所有页面都只通过 OpenAPI 获取数据；没有页面直接读取本地临时 JSON。

## 阶段 2：自动知识工程与 RAG

目标：真实文件进入知识库并能返回可追溯证据。

必须完成：

- 上传、构建任务和状态。
- 解析、切分、索引、检索、重排和引用。
- 质量报告。
- 无答案和跨租户过滤。

门禁：固定评测集 Recall@5 达标；引用可以定位文档和片段；跨组织泄漏为 0。

## 阶段 3：诊断和学习路径

目标：用真实学习数据生成结构化诊断和候选路径。

必须完成：

- 诊断智能体。
- 路径规划智能体。
- 画像版本和知识节点掌握度。
- 诊断和路径的独立意见及证据。

门禁：输出 100% 通过 JSON Schema；固定样本能够重复得到合理结果。

## 阶段 4：资源和测评

目标：两个成长型成员在固定协议下实现较简单智能体。

必须完成：

- 资源生成智能体和资源页面。
- 测评智能体和作答页面。
- 资源和题目都带证据。
- 正确答案只在提交后或后端评分时使用。

门禁：无证据内容不会发布；题目答案可验证；页面覆盖加载、空、失败和成功状态。

## 阶段 5：审核、仲裁与联合决策

目标：从顺序调用升级为真正的多智能体决策。

必须完成：

- 审核智能体能批准、驳回、要求修订和要求人工处理。
- 仲裁智能体能处理分歧、补证据、重试和选择最终动作。
- 有循环上限、超时、失败和降级。
- 保存决策时间线、候选方案和被拒绝原因。

门禁：至少覆盖 5 类预设冲突场景；决策链可以回放。

## 阶段 6：可视化、回归和性能

目标：证明系统做了什么，而不仅是页面能点。

必须完成：

- 时间线、分歧、证据链、画像变化和指标看板。
- 自动和手工回归。
- 成本、延迟、审核驳回率和修复成功率统计。
- 异常文件、模型超时、非法 JSON 和无证据测试。

门禁：高优先级缺陷为 0；演示环境可重复部署。

## 阶段 7：比赛交付

- 冻结接口和范围。
- 三轮完整演示。
- 离线 Mock 和模型失败降级。
- 指标、论文式技术说明、答辩材料与系统行为一致。

门禁：任何宣传数字都能通过固定脚本、版本和数据集复现。
