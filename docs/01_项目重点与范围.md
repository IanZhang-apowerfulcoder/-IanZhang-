# 项目重点与范围

## 一、真正的核心

项目的核心不是网页数量，也不是智能体数量，而是以下能力：

1. 六个智能体具有不同职责和独立输出。
2. 每个关键判断必须绑定证据、置信度和风险。
3. 审核智能体能够否决无证据、矛盾或不可验证结果。
4. 仲裁智能体能够处理分歧、决定重试、补证据、人工介入或执行下一步。
5. 学习结果能够更新画像，并影响下一轮诊断和路径。
6. 决策过程可以回放、比较和量化评测。

## 二、两层系统

### 1. 已发布专业知识库与可选知识工程层

主流程首先加载预先建设、评测并发布的垂直领域 Domain Pack，负责提供可追溯证据、题库、任务库和知识图谱。

后续可选扩展负责：

- 企业文档上传并生成候选知识版本；
- 文档解析、去重、切分和索引；
- RAG 策略配置；
- 候选版本质量评估、人工审批和发布。

它是六智能体的知识基础设施，不计入六个学习决策智能体。自动构建失败时，已发布专业知识库仍必须支持比赛主闭环。

### 2. 六智能体联合决策层

1. 诊断智能体。
2. 学习路径规划智能体。
3. 学习资源生成智能体。
4. 测评智能体。
5. 证据审核与纠偏智能体。
6. 决策与仲裁智能体。

## 三、MVP 必须完成

- 预先建设并验证至少一个垂直领域专业知识库；企业资料自动构建降级为可选扩展。
- 带来源引用的检索。
- 学习者前测和画像。
- 六智能体完成至少一轮联合决策。
- 资源生成、审核、展示。
- 测评生成、审核、作答、评分。
- 学习结果更新画像。
- 决策时间线、证据链和分歧可视化。
- 固定评测集和可复现指标。

## 四、第一版明确不做

- 不拆六个微服务。
- 不做原生手机应用。
- 不追求支持全部文件类型。
- 不把大模型微调作为主要知识存储方式。
- 不实现无法评测的复杂 Graph RAG。
- 不让前端直接调用模型或智能体。
- 不保存或展示模型隐藏推理过程，只保存结构化结论和可审计的理由摘要。

## 五、客观风险

接口固定后，AI 可以显著加速页面和简单逻辑开发，但不能自动保证：

- 权限正确。
- 状态一致。
- 异常可恢复。
- 智能体结果真实可靠。
- 测评答案可验证。
- 多租户不串数据。

因此简单代码可以下放，公共契约、状态机、证据机制、审核、仲裁和发布仍由核心成员负责。
